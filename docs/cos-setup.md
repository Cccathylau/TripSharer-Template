# 腾讯云 COS 香港部署指引

供 Agent 执行部署时参考，也可供使用者手动操作。本文对应当前仓库的本地 COS 上传脚本；控制台名称和服务规则以腾讯云当前说明为准。

## 1. 确认发布方式与访问域名

先完成本地预览，确认发布目标与旅行内容可以公开。创建云资源、修改域名解析和上传网站均需用户授权。

选择 COS 香港地域前，确认用户已有或愿意准备自己的域名。根据腾讯云的[域名合规说明](https://cloud.tencent.com/document/faq/436/102489)，2024 年 1 月 1 日后创建的存储桶，通过默认域名（包括静态网站域名）访问文件会受到预览限制。**不要承诺默认 COS 域名加 `/index.html` 就能正常显示网页，也不要通过修改上传响应头绕过服务限制。**

本方案使用两个地址：

| 配置项 | 用途 | 示例 |
|---|---|---|
| `cosUrl` | 上传脚本解析存储桶与地域 | `https://your-bucket-1250000000.cos.ap-hongkong.myqcloud.com` |
| `siteUrl` | 对外分享与生成分享元数据的 HTTPS 网站根地址 | `https://travel.example.com` |

以上均为示例，请使用用户自己的地址；`siteUrl` 不包含 `/index.html`。上传脚本优先读取 `cosUrl`，没有时才尝试从 `siteUrl` 解析存储桶；自定义域名不能被解析为 COS 存储桶，所以应同时填写两项。

## 2. 准备账号与存储桶

1. 在[腾讯云](https://cloud.tencent.com/)注册或登录，按账号要求完成认证并开通 COS。不要承诺固定审核时间。
2. 创建自己的存储桶，地域选择香港（`ap-hongkong`）；记录包含 APPID 的完整桶名和默认访问域名。
3. 本指引采用公开静态站点方案：公有读、私有写。确认桶内内容均可公开；不要把私密文件放入该桶。已有存储桶时先检查其内容和用途，不直接改变访问权限。

地域、域名和加速方式会影响访问表现及适用要求。涉及 CDN 或其他地域时，核对该方案的域名、备案与计费要求，不把香港存储桶视为所有接入方式的统一结论。

## 3. 配置静态网站与自定义域名

按腾讯云[设置静态网站](https://cloud.tencent.com/document/product/436/32670)和其中的自定义域名指引操作：

1. 开启静态网站，索引文档设为 `index.html`。
2. 当前模板通过单页交互及相对路径加载数据，不要求服务器端路径路由。错误文档按需设置，不必将所有错误返回首页；否则可能把缺失 JSON 伪装成 HTML 响应。
3. 绑定用户的自定义域名，源站类型按静态网站方案配置；根据控制台提供的目标完成 DNS 解析。
4. 配置该自定义域名的 HTTPS 证书和接入方式，再测试访问。不要仅因得到默认静态网站域名就认定已可分享。

若用户没有域名或暂不希望配置，可继续本地预览，或选择 README 中的 GitHub Pages 方案。

## 4. 按需配置 CORS

网页使用相对路径读取 `data/*.json`。HTML 和数据通过相同协议、主机和端口访问时属于同源，通常无需额外 CORS 配置。

仅当网站与数据使用不同来源时，在 COS 中配置跨域规则：来源填写实际网站 Origin（如 `https://travel.example.com`），允许所需的 `GET`、`HEAD` 请求。其他头部按实际请求设置。CORS 不是读取权限，不能替代存储桶授权。

## 5. 提醒费用与可选保护

COS、域名、HTTPS 接入或 CDN 等服务可能产生费用。提醒用户查看所用服务的计费规则即可，预算告警与流量保护不作为发布前置条件。

- 月度预算 30 元、达到 80%（24 元）时提醒，仅为示例。
- 每日费用超过 5 元时提醒，仅为示例。
- 如需限制流量，由用户按预算与可接受的访问中断情况选择支持的保护方式；核实实际单位与生效规则，不混淆流量和带宽。

费用告警不代表自动停止计费。未经授权，不替用户设置预算、限额或超限停用。

## 6. 准备上传凭证

在访问管理 CAM 中创建或使用专用子账号，授权范围限定到目标桶中的网站对象。当前 `scripts/upload-cos.js` 逐文件调用 `putObject`，上传动作需要 `cos:PutObject`，不调用删除接口；不必为了当前脚本授予所有桶写入权限或删除权限。

凭证仅在本地 `.env` 中填写，不在聊天或日志展示，不提交到 Git：

```dotenv
TENCENT_SECRET_ID=your-secret-id
TENCENT_SECRET_KEY=your-secret-key
```

使用者自行在本地填写真实值。已有凭证时保留并核对其适用范围，不借用其他项目凭证。

## 7. 检查并发布

只修改所选行程的配置，保留其他字段：

```js
cosUrl: "https://your-bucket-1250000000.cos.ap-hongkong.myqcloud.com",
siteUrl: "https://travel.example.com",
```

将下方 `my-trip` 替换为实际行程标识。配置发布网址后，先检查数据并重新生成、检查输出：

```bash
node scripts/check-project.js --trip my-trip --stage data
npm run build -- my-trip
node scripts/check-project.js --trip my-trip --stage build
```

前一条成功后再继续。确认输出和预览正常，并已获得发布授权后：

```bash
npm run deploy -- my-trip
```

`deploy` 会再次构建，然后将 `dist/` 下的文件上传到目标桶，覆盖同名对象；**不会读取最新 Notion，也不会自动执行上述数据与构建检查**。需要刷新内容时，先按 Skill 完成 fetch、检查和预览。脚本不会删除桶内旧对象；切换行程或移除内容后，不要认为旧文件已经下线，需单独审查并在获得相应授权后清理。

当前仓库的 GitHub Actions 部署目标是 GitHub Pages，**没有 COS 部署工作流**。本地 COS 发布不需要在 GitHub 添加腾讯云凭证；不要引导用户运行 Fetch Notion Data 来发布到 COS，该流程会提交数据并调用 Pages 部署。

## 8. 线上验收与交接

打开 `siteUrl`（必要时加 `/index.html`），确认 HTTPS、首页、城市切换、分类、地点弹窗、每日路线、攻略和返回操作。检查数据请求与控制台错误，确认更新内容实际可见；上传成功不等于线上验收通过。

| 问题 | 优先检查 |
|---|---|
| 上传 403 | 凭证范围、目标桶和 `cos:PutObject` 权限 |
| 访问 403 | 对象是否存在、公开读取配置及域名接入方案 |
| 网页被下载 | 是否使用受限默认域名；自定义域名与对象响应头是否正确 |
| 跨域错误 | 是否确实跨源、Origin 是否匹配；同时排查 403 等原始错误 |
| JSON 解析错误 | 请求是否误返回错误页/HTML，文件是否上传，gzip 数据是否带 `Content-Encoding: gzip` |
| 更新未生效 | 是否重新 fetch/build/upload，以及浏览器或 CDN 缓存是否过期 |

交接时说明实际发布地址、已验证操作、剩余问题和旧对象处理情况。本文经过文档与脚本核对，不代表该用户的账号、DNS、证书或云部署已实际验收。
